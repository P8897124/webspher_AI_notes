## 1. Purpose

This SOP describes the complete installation, configuration, integration, validation and troubleshooting procedure for IBM HTTP Server 8.5.5 on a new RHEL 8 x86_64 server.

The new IHS server will integrate with an existing IBM WebSphere Application Server Network Deployment 8.5.5 environment managed by Deployment Manager (DMGR).

The final architecture will support:

* HTTP access through port 80.
* HTTPS access through port 443.
* WebSphere plug-in integration.
* Application routing to existing WAS application servers or clusters.
* Remote administration through the WAS Admin Console.
* Plug-in configuration generation and propagation.
* Production logging and operational monitoring.

## 5. Pre-Installation Requirements

### 5.1 Operating System Verification

Execute on the new IHS server:

```bash
cat /etc/redhat-release
uname -m
hostname -f
ldd --version
```

Expected architecture:

```text
x86_64
```

Check disk:

```bash
df -h
```

Check installed system libraries:

```bash
rpm -qa | grep -E 'glibc|libstdc\+\+|libgcc|zlib'
```

Install required operating-system utilities where necessary:

```bash
dnf install -y unzip tar wget net-tools \
  hostname bind-utils lsof nc
```

> The above utilities are administrative conveniences, not a complete IBM prerequisite list. Validate all required libraries against the specific IBM product offering.

### 5.2 Verify Existing WAS Version

Execute on the DMGR server:

```bash
cd $WAS_HOME/bin

./versionInfo.sh
```

Check maintenance packages:

```bash
./versionInfo.sh -maintenancePackages
```

Check installed Installation Manager packages:

```bash
/opt/IBM/InstallationManager/eclipse/tools/imcl \
listInstalledPackages \
-installationDirectory $WAS_HOME
```

Record:

* WAS version.
* WAS fix pack.
* Build level.
* Java SDK level.
* Operating system.
* Cell name.
* DMGR hostname.
* Application server node names.
* Application server HTTP and HTTPS transport ports.

Do not select IHS and plug-in fix packs until the compatibility check is completed.

### 5.3 IBM Compatibility Verification

Use the following IBM resources:

* [IBM Software Product Compatibility Reports](https://www.ibm.com/software/reports/compatibility/clarity/index.html)
* [IBM IHS 8.5.5 installation documentation](https://www.ibm.com/docs/en/ibm-http-server/8.5.5?topic=systems-install-http-server)
* [IBM WAS 8.5.5 IHS installation documentation](https://www.ibm.com/docs/en/was/8.5.5?topic=in-installing-http-server)

Verify all of the following:

* IHS 8.5.5 supports your exact RHEL 8 release and architecture.
* The selected Installation Manager supports the environment.
* The selected plug-in supports your WAS 8.5.5 maintenance level.
* IHS and plug-in levels are compatible.
* WCT/PCT version is appropriate.
* IBM support entitlement covers the intended maintenance level.

> **Important:** WAS 8.5.5 does not mean every IHS 8.5.5 fix pack is automatically supported on every RHEL 8 minor release.

## 7. Installation Procedure

### 7.1 Create the Installation User

Execute as root:

```bash
groupadd ihsgrp

useradd -g ihsgrp -m -d /home/ihsuser ihsuser

passwd ihsuser

mkdir -p /opt/IBM/install

chown -R ihsuser:ihsgrp /opt/IBM
```

Ensure the IHS service account and administration account have the correct permissions. Do not give unrestricted write permissions to production configuration files.

### 7.2 Transfer and Extract Installation Repositories

Transfer the installation archives to:

```text
/opt/IBM/install
```

Example:

```bash
cd /opt/IBM/install

ls -lh
```

Extract the Installation Manager package:

```bash
mkdir -p IMInstaller

unzip agent.installer.linux.gtk.x86_64.zip \
-d IMInstaller
```

Extract product repositories into their corresponding directories:

```bash
mkdir -p IHSRepo PluginRepo WCTRepo

unzip ihs_repository.zip -d IHSRepo

unzip plugins_repository.zip -d PluginRepo

unzip wct_repository.zip -d WCTRepo
```

For multi-part repositories, follow IBM's packaging instructions and extract all parts into the correct common repository structure.

Identify repository configuration files:

```bash
find /opt/IBM/install -name repository.config
```

### 7.3 Install Installation Manager

Switch to the installation user:

```bash
su - ihsuser
```

Execute:

```bash
cd /opt/IBM/install/IMInstaller

./installc -acceptLicense \
-installationDirectory /opt/IBM/InstallationManager
```

Verify:

```bash
/opt/IBM/InstallationManager/eclipse/tools/imcl version
```

Set an environment variable:

```bash
export IMCL=/opt/IBM/InstallationManager/eclipse/tools/imcl
```

### 7.4 Discover the Installation Package IDs

For IHS:

```bash
$IMCL listAvailablePackages \
-repositories /opt/IBM/install/IHSRepo/repository.config
```

For Web Server Plug-ins:

```bash
$IMCL listAvailablePackages \
-repositories /opt/IBM/install/PluginRepo/repository.config
```

For WCT:

```bash
$IMCL listAvailablePackages \
-repositories /opt/IBM/install/WCTRepo/repository.config
```

The usual IHS 8.5.5 package ID is:

```text
com.ibm.websphere.IHS.v85
```

The usual plug-in package ID is:

```text
com.ibm.websphere.PLG.v85
```

Use the actual package IDs and versions returned by your repositories.

### 7.5 Install IBM HTTP Server

```bash
$IMCL install com.ibm.websphere.IHS.v85 \
-repositories /opt/IBM/install/IHSRepo/repository.config \
-installationDirectory /opt/IBM/HTTPServer \
-acceptLicense \
-showProgress \
-log /tmp/ihs_install.log
```

Check:

```bash
/opt/IBM/HTTPServer/bin/httpd -v
```

Check binaries:

```bash
ls -l /opt/IBM/HTTPServer/bin
```

### 7.6 Install Web Server Plug-ins

```bash
$IMCL install com.ibm.websphere.PLG.v85 \
-repositories /opt/IBM/install/PluginRepo/repository.config \
-installationDirectory /opt/IBM/WebPlugins \

-showProgress \
```

### 7.8 Verify All Installed Packages


## 8. Configure the Web Server Plug-in Using PCT

Launch the WebSphere Customization Toolbox on the IHS server.

Open:

```text
WebSphere Customization Toolbox
    → Web Server Plug-ins Configuration Tool
```

Select **Create**.

Enter the following:

| Configuration field  | Value                               |
| -------------------- | ----------------------------------- |
| Web server type      | IBM HTTP Server                     |
| Web server name      | webserver1                          |
| IHS installation     | /opt/IBM/HTTPServer                 |
| Plug-in installation | /opt/IBM/WebPlugins                 |
| HTTP configuration   | /opt/IBM/HTTPServer/conf/httpd.conf |
| HTTP port            | 80                                  |
| Scenario             | Remote                              |
| Architecture         | 64-bit                              |

Complete the wizard.

The PCT tool prepares the plug-in configuration and IHS configuration directives.

Verify:

```bash
grep -i 'WebSpherePluginConfig\|LoadModule.*was' \
/opt/IBM/HTTPServer/conf/httpd.conf
```

The plug-in configuration directive should point to:

```text
/opt/IBM/WebPlugins/config/webserver1/plugin-cfg.xml
```

The initial plug-in file may be a dummy configuration. It must subsequently be replaced with the actual file generated by WAS DMGR.

IBM reference: [Configuring IBM HTTP Server](https://www.ibm.com/docs/en/was/8.5.5?topic=files-configuring-http-server).

## 9. Configure IHS Administration Server

The remote administration server allows the WAS Admin Console to communicate with IHS for supported management tasks.

On the IHS machine:

```bash
cd /opt/IBM/HTTPServer/bin

./setupadm
```

Follow the interactive prompts to create the administration user and group and configure access to the IHS configuration files.

Then configure the administration password file according to the `setupadm` procedure.

Start the administration server:

```bash
./adminctl start
```

Verify:

```bash
ps -ef | grep -i admin
```

Verify the listening port:

```bash
ss -lntp | grep 8008
```

Default administration port:

```text
8008
```

The administration server must have appropriate access to the HTTP Server configuration and plug-in files. It may also need elevated privileges through the supported IHS administration mechanism to perform privileged start/stop operations.

Do not run arbitrary IHS administration scripts with unrestricted root privileges.

IBM reference: [Setting up a remote web server](https://www.ibm.com/docs/en/was-nd/8.5.5?topic=in-setting-up-remote-web-server).

## 10. Configure HTTP and HTTPS

### 10.1 HTTP Configuration

Edit:

```bash
vi /opt/IBM/HTTPServer/conf/httpd.conf
```

Confirm:

```apache
Listen 80
```

Verify the plug-in module and configuration directives are present and correct.

### 10.2 Create the HTTPS Key Database

Obtain a certificate from your enterprise CA.

Create a directory:

```bash
mkdir -p /opt/IBM/HTTPServer/conf/ssl
```

Create a CMS key database using the installed GSKit utility:

```bash
cd /opt/IBM/HTTPServer/bin

./gskcapicmd_64 -keydb -create \
-db /opt/IBM/HTTPServer/conf/ssl/ihs.kdb \
-pw 'USE_A_SECURE_PASSWORD' \
-type cms \
-stash
```

If your installation provides a different GSKit command name, use the executable supplied with that installation.

Generate a certificate signing request, obtain the signed certificate and import the certificate chain using GSKit.

List certificate labels:

```bash
./gskcapicmd_64 -cert -list \
-db /opt/IBM/HTTPServer/conf/ssl/ihs.kdb \
-stashed
```

Record the personal certificate label.

### 10.3 Configure SSL in httpd.conf

Add the appropriate SSL module and listener, checking first that they are not already configured:

```apache
LoadModule ibm_ssl_module modules/mod_ibm_ssl.so

Listen 443

KeyFile /opt/IBM/HTTPServer/conf/ssl/ihs.kdb

<VirtualHost *:443>
    ServerName ihsserver01.example.com
    SSLEnable
    SSLServerCert ihs-cert
</VirtualHost>
```

Replace:

* `ihsserver01.example.com` with your real FQDN.
* `ihs-cert` with the certificate label from GSKit.

Keep HTTP port 80 enabled.

Check syntax:

```bash
/opt/IBM/HTTPServer/bin/apachectl -t
```

Expected:

```text
Syntax OK
```

### 10.4 HTTP-to-HTTPS Behavior

You requested both HTTP and HTTPS. You have two possible operating policies:

* Both protocols serve applications independently.
* HTTP redirects to HTTPS, while HTTPS serves applications.

For production, HTTPS-only application access with an HTTP redirect is generally preferable, provided application and client requirements allow it.

For a redirect, configure an appropriate HTTP virtual host using `mod_rewrite` or a carefully scoped redirect rule. Test application context roots, health checks and load-balancer probes before enabling it globally.

IBM reference: [IBM HTTP Server SSL configuration](https://www.ibm.com/docs/en/linux-on-systems?topic=setup-configuring-http-server-ssl-support).

## 11. Integrate IHS with Existing WAS ND DMGR

This procedure is performed on your existing WAS DMGR environment.

### 11.1 Verify DMGR Status

On the DMGR server:

```bash
cd $WAS_HOME/profiles/Dmgr01/bin

./serverStatus.sh dmgr
```

Expected:

```text
ADMU0508I: The Deployment Manager "dmgr" is STARTED
```

Confirm the cell name:

```bash
$WAS_HOME/bin/wsadmin.sh \
-lang jython \
-conntype SOAP \
-host wasdmgr01 \
-port 8879 \
-user wasadmin \
-password 'PASSWORD' \
-c "print AdminControl.getCell()"
```

Use your organization's approved credential-handling method rather than putting production passwords in command history.

### 11.2 Create an Unmanaged Node

Open the WAS Admin Console:

```text
https://wasdmgr01:9043/ibm/console
```

Navigate:

```text
System Administration
    → Nodes
        → Add Node
```

Select:

```text
Unmanaged Node
```

Enter:

| Field     | Example          |
| --------- | ---------------- |
| Node name | ihsserver01_node |
| Host name | ihsserver01      |
| Platform  | Linux            |

Click **Finish**.

Save the master configuration.

> **Important:** Do not install a WAS Node Agent on the IHS machine just for this integration. The IHS machine is represented as an unmanaged node.

### 11.3 Create a Web Server Definition

Navigate:

```text
Servers
    → Server Types
        → Web servers
            → New
```

Select the newly created unmanaged node.

Enter:

| Field                  | Example                             |
| ---------------------- | ----------------------------------- |
| Web server name        | webserver1                          |
| Web server type        | IBM HTTP Server                     |
| Host name              | ihsserver01                         |
| Port                   | 80                                  |
| Installation directory | /opt/IBM/HTTPServer                 |
| Plug-in directory      | /opt/IBM/WebPlugins                 |
| Configuration file     | /opt/IBM/HTTPServer/conf/httpd.conf |
| Administration port    | 8008                                |

Configure the remote administration credentials.

For the administration protocol, use the protocol actually configured on the IHS Administration Server. Do not confuse that connection with client-facing HTTPS on port 443.

Choose application mapping carefully:

* Select `ALL` if you want all eligible existing applications mapped to the web server.
* Select `None` if you intend to map only selected applications.

Save the configuration.

### 11.4 Verify Web Server Definition

Navigate:

```text
Servers
    → Server Types
        → Web servers
```

Expected:

```text
webserver1
```

The remote web server definition should now be registered in the DMGR master repository.

IBM official procedure: [Setting up a remote web server in WAS ND 8.5.5](https://www.ibm.com/docs/en/was-nd/8.5.5?topic=in-setting-up-remote-web-server).

## 12. Generate and Propagate plugin-cfg.xml

This is one of the most important integration steps.

### 12.1 Generate Plug-in Configuration

In the DMGR Admin Console:

```text
Servers
    → Server Types
        → Web servers
            → webserver1
```

Select:

```text
Generate Plug-in
```

Wait for successful generation.

The generated file contains routing details such as:

* Application context roots.
* Virtual host information.
* Cluster members.
* Application server transport ports.
* Load-balancing information.
* Transport security requirements, where configured.

### 12.2 Propagate Plug-in Configuration

From the same web server page:

```text
Propagate Plug-in
```

Verify that the operation completes successfully.

The expected destination is:

```text
/opt/IBM/WebPlugins/config/webserver1/plugin-cfg.xml
```

On the IHS machine:

```bash
ls -l /opt/IBM/WebPlugins/config/webserver1/plugin-cfg.xml
```

Check the modification timestamp:

```bash
stat /opt/IBM/WebPlugins/config/webserver1/plugin-cfg.xml
```

If automatic propagation fails, inspect the administration server connection, credentials, permissions and firewall. A controlled manual transfer of the generated file is an alternative, provided the correct web-server-specific file is copied to the configured plug-in path.

### 12.3 Check the Generated Configuration

```bash
grep -E 'ServerCluster|Transport|VirtualHostGroup|UriGroup' \
/opt/IBM/WebPlugins/config/webserver1/plugin-cfg.xml
```

Confirm that the intended WAS cluster and application servers are represented.
